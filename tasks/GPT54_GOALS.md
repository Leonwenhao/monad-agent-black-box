Use these as independent Codex `/goal` objectives. Each goal must keep working until its pass/fail criteria are satisfied, or stop with a precise blocker and evidence.

Important: do not reinterpret the product. Follow `docs/AGENT_BLACK_BOX_BUILD_SPEC.md`.

## Goal 0: Verify Local Goal Loop

Objective:

> Verify Codex `/goal` support is active in an interactive persisted local thread before starting implementation.

Pass criteria:

- `codex features list` shows goals enabled.
- `/goal` is available in the interactive TUI.
- Current work is in a persisted local thread, not an ephemeral exec-only session.

Fail criteria:

- `/goal` is unavailable.
- Codex reports ephemeral thread or missing state database.

If fail:

- Restart Codex in interactive TUI mode.
- Recheck feature state.
- Continue manually only if the hackathon clock requires it.

## Goal 2: Implement TraceRegistry Contract

Objective:

> Implement `TraceRegistry.sol` and tests exactly for the P0 contract scope.

Pass criteria:

- Tests cover session start.
- Tests cover trace recording.
- Tests cover execution linking.
- Tests cover session close.
- Tests reject duplicate session IDs.
- Tests reject writes by non-owner.
- Tests reject writes to missing session.
- Tests reject writes to closed session.
- Contract stores no long reasoning strings beyond URI/event metadata.

Fail criteria:

- Anyone can write to another owner's session.
- Final tx hash cannot be linked.
- Event schema does not support the frontend proof panel.

## Goal 3: Implement DemoTreasuryAction Contract

Objective:

> Implement the simple final-action contract used in the demo.

Pass criteria:

- `executeAction` emits `DemoActionExecuted`.
- Action includes `sessionId`, caller, action type, amount, and memo.
- Tests prove it can be called by the runner wallet.
- Tests prove emitted event can be linked back to `TraceRegistry`.

Fail criteria:

- Contract introduces real asset custody complexity.
- Demo action cannot be called on testnet without special setup.

## Goal 4: Implement Trace Schema And Hashing

Objective:

> Implement a deterministic trace JSON schema and hash utility used by runner and frontend.

Pass criteria:

- Trace entry type includes all required fields.
- JSON canonicalization is deterministic.
- Hash output is compatible with Solidity `bytes32`.
- Unit tests prove the same payload hashes identically across runs.
- Bad or missing fields are rejected.

Fail criteria:

- Hash depends on object key insertion order.
- Frontend and runner use different hashing rules.

## Goal 5: Implement Deterministic Demo Runner

Objective:

> Implement the no-LLM scripted demo runner that creates a full Agent Black Box session.

Pass criteria:

- Runner can start a session on local chain.
- Runner records all required trace event types.
- Runner writes JSON trace files.
- Runner executes `DemoTreasuryAction`.
- Runner links final tx hash back to registry.
- Runner prints a final summary with session ID, addresses, event count, and tx hashes.
- Runner works with no API keys.

Fail criteria:

- LLM availability is required.
- Runner cannot be rerun cleanly.
- Hashes recorded on-chain differ from JSON hashes.
